## Run it (Windows x64)

Extract the whole `saige-windows-x64-demo` archive into one folder and run `Launch.cmd`. WASD moves, the up and down arrows
rise and descend, right-drag looks, Escape closes. A Vulkan 1.3 loader and a compatible driver are required; the archive ships
no driver, software Vulkan runtime or validation layer. See the README inside the archive and `renderer-diagnostics.md`.

## Build from source

```powershell
cmake --preset windows-release -DSAIGE_ENABLE_VULKAN=ON -DSAIGE_VULKAN_FETCH_HEADERS=ON
cmake --build --preset windows-release --parallel
ctest --preset windows-release
.\build\windows-release\Release\saige_desktop.exe --scene examples\textured-scene\saige.scene.json --require-rendered
```

Linux: configure with `-DSAIGE_ENABLE_VULKAN=ON -DSAIGE_VULKAN_FETCH_HEADERS=ON`, build, and run `ctest` (set
`SAIGE_REQUIRE_VALIDATION=1` to make a missing validation layer a failure).

## Known limitations (state these in any announcement)

- **Software Vulkan only.** Every rendering result above ran on a CPU rasterizer (Mesa Lavapipe/llvmpipe). Timings are CPU
  numbers. No physical-GPU result exists; that evidence is tracked in #9 and must not be implied.
- The validation layer in these runners does not detect hazards on descriptor (shader) reads, so synchronization tests of
  sampled textures prove contents, not ordering; the capability probe reports this explicitly.
- Materials sample base color only. Other glTF texture slots are reported as importer warnings. Blend materials draw opaque.
- Only the scene pass is GPU-timed, and the memory-budget path has only been exercised on Lavapipe.
- Vulkan 1.3 is required. Vulkan 1.4 support is planned for 0.3 (#43) with the 1.3 path retained.
- Physical Windows GPU and vendor-driver presentation remain outstanding (#9).
