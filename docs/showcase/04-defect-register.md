# Showcase 04 defect register

Permanent record of the defects found in the delivered Showcase 04 film ("SAIGE - A World Alive", master `SAIGE_A_World_Alive.mp4`, SHA-256 `00dcf1fd...b84d`, film source `50ca1f3`) by independent
review and by our own inspection, with the cause, the engine subsystem, the correction and the evidence. It is updated whenever an entry changes; nothing is deleted. Branch of the corrections:
`claude/s04-quality`. Showcase 05 is not authorised while a **Critical** entry is not Fixed. The film itself is not re-rendered: corrections are shown with short single-frame captures of the same
frames of the same seed (`saige_alive --film ... --frames N`), and guarded by tests that render those frames.

**Status words.** *Fixed*: cause found, change made, regression test fails without the change (mutant caught). *Root-caused*: cause known, no change yet. *Investigated*: evidence gathered, cause not
yet known. *Open*: not yet investigated. A status is only raised when the evidence in its row exists.

**Severity.** Critical: visibly wrong geometry or rendering in the film. High: wrong behaviour or a large realism gap. Medium: noticeable. Low: minor or latent.

**Where the film's footage was wrong, by subsystem.** Most Critical defects were in the *showcase's world authoring and scene assembly* (`showcase/04-world-alive`), not in the engine renderer: the district
generator, the mesh builder that turns it into models, the scenery tiling and the director. That is the part a world editor will own, which is why the validator below exists.

## The validator and its contract (for the world editor)

`showcase/04-world-alive/src/district_validate.{hpp,cpp}`, run by `alive_validate [seed...] [-v]` and by `alive_validate_test`. Contract version 1. It reads `District` (data) only, never meshes, so any
authoring tool that can produce a `District` gets the same checks; a finding has a stable `code`, a `severity`, a position and the ids involved.

| Code | Severity | Meaning | `ids` |
| --- | --- | --- | --- |
| `BLD_OVERLAP` | critical | building footprints overlap | building, building |
| `BLD_ON_ROAD`, `BLD_ON_SIDEWALK` | critical, error | a building stands on the roadway or the sidewalk | building |
| `WALL_COPLANAR` | critical | two buildings' faces lie in one plane with overlapping extent (depth-buffer fight) | building, building |
| `PROP_ON_ROAD`, `PROP_IN_PARKING` | error | an outdoor prop on the roadway or in a parking bay | prop, (spot) |
| `PROP_IN_BUILDING` | error | an outdoor prop inside a footprint | prop, building |
| `PROP_OVERLAP` | error / warning | two props overlap (> 0.02 m2 error) | prop, prop |
| `PARKING_ON_BUILDING`, `PARKING_ON_SIDEWALK`, `PARKING_OFF_ROAD` | error, warning, warning | a bay overlaps a building or the sidewalk, or is not on the road | spot, (building) |
| `ROOM_FURNITURE_OUTSIDE`, `ROOM_FURNITURE_IN_WALL`, `ROOM_FURNITURE_OVERLAP` | error | furniture through, in a wall, or overlapping other furniture | building, piece, (piece) |
| `DOOR_BLOCKED`, `STAIR_BLOCKED`, `STAIR_TOP_BLOCKED` | error | furniture in the doorway strip, on the stairs or foot landing, or on the top landing | building, piece |

Also exported for authoring tools: `exposed_face_spans` (what part of a wall is visible), `face_frame`, `interior_wall_face_mask`, and `vegetation_shape.hpp` (the canopy as spheres). Coordination with
Gemini's world editor is on issue #43: the editor should call `validate_district` on every save and refuse to publish a world with an `error` or `critical` finding; new rules are added here with a
test that injects the defect.

## Tests that guard the corrections

* `alive_validate` (`validate_test.cpp`): 16 generated districts have no blocking finding; every defect class is injected into a clean district and must be reported; exact geometry cases.
* `alive_visual` (`tools/visual_regression.py`): renders film frames twice with one controlled difference and compares pictures; `--mutants` switches each film behaviour back on and requires the case to fail.
  Needs the renderer and the Poly Haven cache; skipped (exit 77) otherwise. Software Vulkan only: nothing here is physical-GPU evidence.
* `alive_district`, `alive_world`, `alive_traffic`: unchanged and passing after the corrections (world: worst overlap 0, none stuck; traffic: accident, response, 0 red-light runs).

A passing CTest run is not sufficient on its own: the visual cases exist because the numeric tests passed on the film's data while the picture was wrong.
